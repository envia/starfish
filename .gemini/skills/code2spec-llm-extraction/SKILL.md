# Skill: LLM-Based AST Extraction

## Objective
Extract ENUMs, constants, and IPC patterns from AST data using Cline's NATIVE LLM (not stub LLMClient). This skill processes prompts generated by `llm_extract_cli.py --generate-prompts-only` and saves JSON results for merging.

## When to Use
- Workflow Step 3-1e.2 in `code2spec-discovery.md`
- When prompt files exist in `${ANALYSIS_DIR}/llm-extraction/`
- After running `--generate-prompts-only` mode

## Instructions

### Step 1: Locate Prompt Files

Find the generated prompt files in the analysis directory:
```
${ANALYSIS_DIR}/llm-extraction/
├── llm-enum-prompt.md
├── llm-constant-prompt.md
└── llm-ipc-prompt.md
```

### Step 2: Process Each Prompt with NATIVE LLM

**CRITICAL**: Use YOUR NATIVE LLM to analyze each prompt. Do NOT call any CLI command that uses `LLMClient.generate()` - those are stubs.

For EACH prompt file:

1. **Read the prompt file** using `read_file` tool
2. **Analyze the content** using YOUR NATIVE LLM capabilities
3. **Extract data** following the prompt's output format instructions
4. **Return ONLY valid JSON** (no markdown, no explanations)
5. **Save JSON** to the corresponding result file using `write_to_file`

### Step 3: Output Format Requirements

#### ENUM Results (`llm-enum-results.json`)
```json
[
  {
    "name": "ClassName.EnumName",
    "values": ["VALUE1", "VALUE2", "VALUE3"],
    "type": "language_enum",
    "language": "java|kotlin|cpp|...",
    "source": "[Source: file/path.ext:line_number]"
  }
]
```

#### Constant Results (`llm-constant-results.json`)
```json
[
  {
    "name": "CONSTANT_NAME",
    "value": "actual_value",
    "type": "language_const|error_code",
    "language": "java|kotlin|cpp|...",
    "source": "[Source: file/path.ext:line_number]"
  }
]
```

#### IPC Results (`llm-ipc-results.json`)
```json
[
  {
    "mechanism": "binder|socket|broadcast_receiver|...",
    "name": "ComponentName",
    "source_component": "SourceComponent",
    "target_component": "TargetComponent",
    "data": "Description of data exchanged",
    "source": "[Source: file/path.ext:line_number]"
  }
]
```

### Step 4: Save Results

Save each JSON result to the corresponding file:
- ENUM → `${ANALYSIS_DIR}/llm-extraction/llm-enum-results.json`
- Constant → `${ANALYSIS_DIR}/llm-extraction/llm-constant-results.json`
- IPC → `${ANALYSIS_DIR}/llm-extraction/llm-ipc-results.json`

### Step 5: Verify Results

After saving, verify each file:
1. Valid JSON format (parseable)
2. Each entry has `[Source: file:line]` citation
3. ENUM names are qualified (e.g., `ClassName.EnumName`, not just `Type`)
4. At least some items extracted per category

## Zero Inference Compliance

**CRITICAL RULES:**
1. **NO inference**: Only extract what is explicitly in the source code
2. **Source citation required**: Every entry MUST have `[Source: file:line]`
3. **Qualified names**: ENUM names must include enclosing class/file
4. **No hallucination**: If source doesn't show it, don't extract it

> **Note — this `[Source: file:line]` is the *machine intermediate* format of the extraction JSON (`.analysis/llm-extraction/*.json`).**
> In the final document `09-ipc-enum-catalog.md`, render that file:line as a **backticked deep link**
> (``[`file/symbol`](src:path#L<line>)`` — the host prefix is prepended at render time from `repo.json.deepLink.base`).

## Error Handling

If a prompt file is missing:
- Log warning: `[WARNING] Prompt file not found: {path}`
- Continue with remaining prompts
- Do NOT fail the entire extraction

If JSON parsing fails:
- Log error: `[ERROR] Failed to parse JSON: {error}`
- Retry extraction for that category
- If still fails, skip that category

## Completion

After processing all three prompts:
1. Confirm all three result files exist
2. Report extraction counts:
   - ENUMs: N items
   - Constants: N items
   - IPC Patterns: N items
3. Workflow can proceed to Step 3-1e.3 (merge results)
