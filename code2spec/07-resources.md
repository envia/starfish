Starfish is a C++ web browser engine, and the tracked static resources found are test infrastructure (test-list files, reference fonts, capture clients) plus the embedded engine resources listed below (the user-agent stylesheet and, on Windows, a generated Fontconfig configuration). Tracked binary/text asset counts from `git ls-files`: 307 `.res` files, 26 `.png` files, 4 `.ttf` files.

## Static Asset Structure

**What a `.res` file is in this repository:** a plain-text test-list file, one test URL (or test path) per line, optionally prefixed with `#` annotation lines (e.g. `# [auto-fail:IMG_MISMATCH] http://web-platform.test:8000/...` in [tool/wpt/reftest_lists/content-security-policy.res](src:tool/wpt/reftest_lists/content-security-policy.res)). The WPT runner "Reads a `.res` list (or a directory of them) of WPT URLs, runs each in the Starfish shell in parallel" ([tool/wpt/scripts/wpt_runner.py](src:tool/wpt/scripts/wpt_runner.py#L18)), and [tool/wpt/scripts/wpt_manifest_lists.py](src:tool/wpt/scripts/wpt_manifest_lists.py#L16) exists to "Generate per-spec `.res` URL lists for a non-testharness WPT test type" from the WPT `MANIFEST.json`. The pixel-test driver dispatches on the extension (`if [[ "$tc" == *".res" ]]` in [tool/pixel_test/pixel_test.sh](src:tool/pixel_test/pixel_test.sh#L41)), and [tool/reftest/update_regression.sh](src:tool/reftest/update_regression.sh#L4) copies `tool/reftest/*.res` lists into `test/regression/...` test names.

**Font configuration as an embedded resource (Windows).** On Windows builds, Fontconfig "has no usable system-wide configuration", so instead of shipping `fonts.conf` files, a flattened build-time snapshot of the configuration is compiled in: [`loadWindowsFontconfigConfig`](src:src/public/delegate/LWEDelegate.cpp#L63) joins the generated string chunks `g_windowsFontconfigConfigXmlChunks` (kept as separate literals to stay under MSVC's 65535-byte string-literal limit) and loads them with `FcConfigParseAndLoadFromMemory` ([src/public/delegate/LWEDelegate.cpp](src:src/public/delegate/LWEDelegate.cpp#L76)), then `FcConfigBuildFonts`/`FcConfigSetCurrent`. It is called from [`LWE::Initialize`](src:src/public/delegate/LWEDelegate.cpp#L88) at [line 135](src:src/public/delegate/LWEDelegate.cpp#L135). The included header `WindowsFontconfigConfig.h` is generated at build time into `starfish_generated/` by [tool/build/gen_windows_fontconfig_config.py](src:tool/build/gen_windows_fontconfig_config.py) as wired in [build/windows_vcpkg.cmake](src:build/windows_vcpkg.cmake#L93). No other `fontconfig`/`FcConfig` usage was found under `src/` (grep for `fontconfig|FcInit|FcConfig` matched only `LWEDelegate.cpp`).

## Internationalization

There is no translation-resource system (no message catalogs, `.po`/`.mo` files, or localized string tables were found) — Not specified in code. The internationalization-related code found consists of text encoding, Unicode processing, and locale-aware text segmentation built on ICU:

- **ICU is included globally** from [src/StarfishBase.h](src:src/StarfishBase.h#L236): under `STARFISH_ENABLE_RUNTIME_ICU_BINDER` it uses `RuntimeICUBinder.h`/`ICUPolyfill.h` ([lines 237-238](src:src/StarfishBase.h#L237)); on Windows it includes `<icu.h>` ([line 241](src:src/StarfishBase.h#L241)); otherwise it includes `<unicode/locid.h>`, `<unicode/brkiter.h>`, `<unicode/ubidi.h>`, `<unicode/uchar.h>`, `<unicode/ucnv.h>`, `<unicode/ucsdet.h>`, `<unicode/uscript.h>`, `<unicode/unorm.h>`, `<unicode/rbbi.h>` ([lines 243-251](src:src/StarfishBase.h#L243)).
- **Charset conversion and detection**: [`TextConverter`](src:src/core/util/TextConverter.h#L27) wraps an ICU converter opened with `ucnv_open` ([src/core/util/TextConverter.cpp](src:src/core/util/TextConverter.cpp#L52)). Its second constructor ([line 61](src:src/core/util/TextConverter.cpp#L61)) first honors a `charset=` parameter parsed from the MIME type ([line 67](src:src/core/util/TextConverter.cpp#L67)); failing that, it runs ICU charset detection (`ucsdet_open`/`ucsdet_setText`/`ucsdet_detectAll`/`ucsdet_detect`, [lines 95-110](src:src/core/util/TextConverter.cpp#L95)) over at most the first 1024 bytes ([line 97](src:src/core/util/TextConverter.cpp#L97)).
- **Locale-aware line breaking**: [`LineBreakIteratorPool`](src:src/core/util/LineBreakerIteratorPool.h#L50) caches `UBreakIterator*` instances keyed by [`BreakIteratorInfo`](src:src/core/util/LineBreakerIteratorPool.h#L35) (locale string + [`LineBreakIteratorMode`](src:src/core/util/LineBreakerIteratorPool.h#L28), the UAX-14 default/loose/normal/strict variants); [`get`](src:src/core/util/LineBreakerIteratorPool.h#L64) takes `(locale, mode, isCJK)` and opens new iterators via [`openLineBreakIterator`](src:src/core/util/LineBreakerIteratorPool.h#L46). The pool is created per engine instance in [src/Starfish.cpp](src:src/Starfish.cpp#L83).
- **Locale plumbing**: the locale is supplied by the embedder as a string — the [`WebWorker`](src:src/core/modules/worker/WebWorker.h#L34) constructors take `const char* locale, const char* timezoneID`, and worker host processes receive it through [`WorkerHostInitData`](src:src/core/modules/worker/WorkerHostInitData.h#L25), which carries `locale`, `timezoneID`, and `userAgent` fields ([line 28](src:src/core/modules/worker/WorkerHostInitData.h#L28)). How a default locale value is chosen is Not specified in code (in the files read for this chapter).

## Design System

Not applicable as a UI component/theme design system — Starfish is a browser engine, not an application UI: the `src/` tree contains only `binding`, `browser`, `core`, `launcher`, `platform`, `public`, and `shell` (plus engine sources), with no theme, design-token, or UI-kit directory; `src/core/style/` holds the CSS engine implementation itself.

The engine does ship one default-style resource: the **user-agent stylesheet** [src/core/style/UserAgentStyleSheet.css](src:src/core/style/UserAgentStyleSheet.css) (414 lines written as C string literals, e.g. `"html {" "display: block;" "}"`, giving default `display` values such as `html`/`body` → `block` and `head`/`meta`/`title`/`noscript`/`link`/`style` → `none`). It is textually embedded into the engine with `#include "core/style/UserAgentStyleSheet.css"` initializing a `const char ua[]` in [src/core/dom/Document.cpp](src:src/core/dom/Document.cpp#L224). At document setup the code asserts the sheet contains no `important` rules ([line 227](src:src/core/dom/Document.cpp#L227)), parses it into a `CSSStyleSheet` ([line 228](src:src/core/dom/Document.cpp#L228)), flags every rule with `setIsUARule(true)` ([line 238](src:src/core/dom/Document.cpp#L238)), and registers it with the style resolver via `addSheet` ([line 241](src:src/core/dom/Document.cpp#L241)).
