This chapter documents the design principles, module decomposition, recurring design patterns, dependency wiring, naming rules, inheritance structures, and error-handling mechanisms of the Starfish web browser engine ("a lightweight Web browser engine for TV, mobile, headless and wearable devices", [`README.md`](src:README.md#L3)). Every claim below is backed by code or project documentation that was read directly; anything the code does not state is marked "Not specified in code".

## Design Principles

The project's own C++ style guide (`docs/Coding_Style_Guide.md`) states the following principles explicitly:

- **Google C++ Style Guide as the baseline.** "Our coding style generally follows Google C++ Style Guide" ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L3)). Mechanical formatting is delegated to the project-root `.clang-format` file and enforced by `tool/lint/check_tidy.py` in CI ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L7)).
- **Include discipline / dependency minimization.** Headers should be included only in `.cpp` files; including a header inside another header is allowed only for class inheritance and by-value class members, otherwise forward declarations are required ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L30)).
- **No RTTI.** "Do not use Run Time Type Information." ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L251)). Instead, virtual type predicates are used, e.g. [`isResizeObserver`](src:src/core/modules/resize_observer/ResizeObserver.h#L56).
- **Restricted exceptions.** "Do not use try-catch statements except throwing a DOMException." ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L268)) — see [Error Handling Patterns](#error-handling-patterns).
- **GC-based memory model with typed nullability.** The codebase is GC-based and passes objects as raw pointers that are expected to be valid by default; absence must be expressed in the type with `Optional<T>` ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L271)). Starfish terminates with an error message when a memory allocation attempt fails ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L272)), and GC-managed pointers must not be held in non-GC containers such as `std::vector` — `GCVector`/`GCTightVector` must be used instead ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L275)).
- **Assertions reserved for real invariants.** Blanket-asserting every pointer argument is declared a legacy pattern that must not be extended ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L285)); `String*` must never be `nullptr` — `String::emptyString` or `Optional<String*>` is used instead ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L291)).
- **Modern C++ subset.** C++11 features are encouraged ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L254)), `enum class` is preferred over plain `enum` ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L258)), and every overriding virtual function must be marked `override` ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L263)).

**Layered separation observable in include boundaries.** Engine-core code consumes platform services through headers under `src/platform/`: for example, the layout code includes the platform loader ([`FrameBox.cpp`](src:src/core/layout/FrameBox.cpp#L47) includes `platform/loader/ResourceLoader.h`). The boundary is a directory convention rather than a strictly one-way dependency — platform code also includes core headers (e.g. [`FontResource.cpp`](src:src/platform/loader/FontResource.cpp#L22) includes `core/dom/Document.h`). A strict binary boundary does exist at the embedder-API layer: the delegate contract headers under `src/public/contract/` "form a binary compatibility boundary" between the installed public API library and a separately delivered impl library ([`uwe.md`](src:docs/uwe.md#L4)).

## Dependency Management

**Git submodules.** Third-party code is vendored through 24 git submodules declared in `.gitmodules` (count verified). Examples: the Escargot JavaScript engine at `third_party/escargot` ([`.gitmodules`](src:.gitmodules#L9)), `third_party/libwebsockets` ([`.gitmodules`](src:.gitmodules#L64)), `third_party/openssl` ([`.gitmodules`](src:.gitmodules#L67)), `third_party/googletest` ([`.gitmodules`](src:.gitmodules#L79)), the WPT test suite at `third_party/wpt` ([`.gitmodules`](src:.gitmodules#L85)), and the binding generator at `binding_generator` ([`.gitmodules`](src:.gitmodules#L5)).

**CMake wiring.** The root build splits by OS: Windows includes `build/version.cmake` and `build/windows.cmake`, all other platforms include `build/version.cmake`, `build/config.cmake`, `build/third_party.cmake`, `build/starfish.cmake`, and `build/starfish_public_api.cmake` ([`CMakeLists.txt`](src:CMakeLists.txt#L88)–L96), with worker libraries added conditionally via `build/worker.cmake` ([`CMakeLists.txt`](src:CMakeLists.txt#L116)). Inside `build/third_party.cmake`, Escargot is built in-tree with `ADD_SUBDIRECTORY (third_party/escargot)` ([`third_party.cmake`](src:build/third_party.cmake#L394)), `skia_matrix` is compiled directly into a shared library from globbed sources ([`third_party.cmake`](src:build/third_party.cmake#L47)), and the link set is collected as `SET (STARFISH_LIBRARIES_THIRD_PARTY ${GC_TARGET} skia_matrix clipper escargot)` ([`third_party.cmake`](src:build/third_party.cmake#L643)).

**vcpkg for Windows.** `build/windows.cmake` includes the vcpkg glue ([`windows.cmake`](src:build/windows.cmake#L234)); `build/windows_vcpkg.cmake` selects the `x86-windows`/`x64-windows` triplet ([`windows_vcpkg.cmake`](src:build/windows_vcpkg.cmake#L14)). The manifest [`vcpkg.json`](src:vcpkg.json#L5) declares the Windows native dependency graph: `curl` (features `ssl`, `sspi`), `libwebsockets`, `cairo` (features `fontconfig`, `freetype`), `harfbuzz`, `fontconfig`, `freetype`, `giflib`, `glew`, `libpng`, `pthreads`.

## Error Handling Patterns

The style guide constrains error handling: try-catch is forbidden except for `DOMException` ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L268)), and a failed memory allocation terminates the engine with an error message ([`Coding_Style_Guide.md`](src:docs/Coding_Style_Guide.md#L272)).

| Exception/mechanism | Where raised | Handling | Source |
|---|---|---|---|
| `DOMException` (thrown C++ exception) | Spec-defined DOM error paths, e.g. `throw new DOMException(..., INVALID_NODE_TYPE_ERR)` in [`Range.cpp`](src:src/core/dom/Range.cpp#L149) | Caught only as `DOMException*` at controlled boundaries, e.g. `catch (DOMException* e)` in [`WorkerGlobalScope.cpp`](src:src/core/modules/worker/WorkerGlobalScope.cpp#L189); the class carries a spec `Code` enum and message | [`DOMException`](src:src/core/dom/DOMException.h#L27) |
| `DOMExceptionOr<T>` (error-or-value return) | Returned by fallible operations instead of throwing, e.g. static [`checkUsability`](src:src/core/dom/canvas/CanvasImageSource.h#L36) returning `DOMExceptionOr<bool>` | Caller branches on [`isDOMException`](src:src/core/dom/DOMExceptionOr.h#L60) and extracts `asDOMException()`/`asOtherType()`; the type is stack-only via `STARFISH_MAKE_STACK_ALLOCATED()` at [`DOMExceptionOr.h`](src:src/core/dom/DOMExceptionOr.h#L31); a `void` specialization exists at [`DOMExceptionOr<void>`](src:src/core/dom/DOMExceptionOr.h#L85) | [`DOMExceptionOr`](src:src/core/dom/DOMExceptionOr.h#L29) |
| `STARFISH_ASSERT` / `STARFISH_ASSERT_NOT_REACHED` (debug assertions) | Invariant checks, e.g. [`Optional::value`](src:src/StarfishBase.h#L748) asserts `hasValue()`; unreachable code, e.g. [`Node.cpp`](src:src/core/dom/Node.cpp#L1017) | Map to `assert()` in debug builds ([`STARFISH_ASSERT`](src:src/StarfishBase.h#L483), [`STARFISH_ASSERT_NOT_REACHED`](src:src/StarfishBase.h#L484)); compiled to `((void)0)` under `NDEBUG` ([`StarfishBase.h`](src:src/StarfishBase.h#L479)) | [`STARFISH_ASSERT`](src:src/StarfishBase.h#L483) |
| `STARFISH_RELEASE_ASSERT` / `STARFISH_RELEASE_ASSERT_SHOULD_NOT_BE_HERE` / `STARFISH_CRASH` (fatal, release builds) | Conditions that must hold even in release, e.g. [`Avplay.cpp`](src:src/core/extra/Avplay.cpp#L208); `STARFISH_CRASH` is an alias defined at [`StarfishBase.h`](src:src/StarfishBase.h#L476) and remapped as `CRASH` in [`CanvasRenderingContext2DMixIn.cpp`](src:src/core/dom/canvas/CanvasRenderingContext2DMixIn.cpp#L62) | Logs `RELEASE_ASSERT` via `STARFISH_LOG_ERROR` and calls `::abort()` ([`STARFISH_RELEASE_ASSERT`](src:src/StarfishBase.h#L499), [`STARFISH_RELEASE_ASSERT_SHOULD_NOT_BE_HERE`](src:src/StarfishBase.h#L506)) | [`STARFISH_RELEASE_ASSERT`](src:src/StarfishBase.h#L499) |
| Logging macros `STARFISH_LOG_ERROR` / `STARFISH_LOG_WARN` / `STARFISH_LOG_INFO` | Recoverable failures are logged in place, e.g. lws write failure in [`SocketLWS.cpp`](src:src/core/modules/networking/SocketLWS.cpp#L96) | Per-platform expansion: Tizen `dlog_print`, Android `__android_log_print`, Windows forwarders, otherwise `fprintf` to stderr/stdout ([`STARFISH_LOG_ERROR`](src:src/StarfishBase.h#L429), [`STARFISH_LOG_INFO`](src:src/StarfishBase.h#L407)); INFO output is filtered through `LoggerOption::instance()->isLogEnable(...)` ([`StarfishBase.h`](src:src/StarfishBase.h#L408)) | [`STARFISH_LOG_ERROR`](src:src/StarfishBase.h#L429) |
| `RETURN_FALSE_IF_FAILED` (early-return guard) | Serialization/IO chains, e.g. cache stream writing in [`FetchCacheStream.cpp`](src:src/core/modules/serviceworker/FetchCacheStream.cpp#L118) | Logs a warning with `STARFISH_LOG_WARN` and returns `false` from the enclosing function | [`RETURN_FALSE_IF_FAILED`](src:src/StarfishBase.h#L512) |
