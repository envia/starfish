Starfish is "a lightweight Web browser engine for TV, mobile, headless and wearable devices" ([`README.md`](src:README.md#L3)). It is configured and built with CMake + Ninja ([`README.md`](src:README.md#L51)), targets Ubuntu, Tizen, Windows and Android ([`README.md`](src:README.md#L8)), and is deployed as a Tizen RPM ([`lightweight-web-engine.spec`](src:packaging/lightweight-web-engine.spec#L19)), a Windows DLL/shell built with vcpkg ([`README.md`](src:README.md#L216)), an Android Gradle build ([`README.md`](src:README.md#L291)), or a plain Linux executable/library.

## Build Pipeline

**Configure.** The reference Ubuntu configure command is `cmake -Bout/release -DCMAKE_BUILD_TYPE=Release -DBACKEND=glib_cairo_gl -DSHELL=x11 -DTARGETNAME=Starfish -G Ninja` ([`README.md`](src:README.md#L51)). The top-level [`CMakeLists.txt`](src:CMakeLists.txt#L88) routes the build: `Windows` includes `build/version.cmake` + `build/windows.cmake`; every other platform includes `version.cmake`, `config.cmake`, `third_party.cmake`, `starfish.cmake` and `starfish_public_api.cmake`, plus `build/test/prepare_test.cmake` on Linux or when `ENABLE_TEST=1` ([`CMakeLists.txt`](src:CMakeLists.txt#L97)), `build/starfish_shell.cmake` when `SHELL` is set ([`CMakeLists.txt`](src:CMakeLists.txt#L101)), and the Tizen TPK/UWE files on Tizen ([`CMakeLists.txt`](src:CMakeLists.txt#L105)). A `lightweight-web-engine.pc` pkg-config file is generated from `lightweight-web-engine.pc.in` ([`CONFIGURE_FILE`](src:CMakeLists.txt#L112)).

**IDL binding generation (configure time).** JS bindings for spec-defined interfaces are generated from `src/**/*.idl` at cmake configure time; after adding/editing/deleting any `.idl` the cmake command must be re-run — an incremental `ninja` alone will not regenerate them ([`README.md`](src:README.md#L55)). [`binding.cmake`](src:build/binding.cmake#L10) requires a Python 3 interpreter, globs all IDL files plus the generator scripts/templates from the `binding_generator` submodule ([`binding.cmake`](src:build/binding.cmake#L28), [`.gitmodules`](src:.gitmodules#L5)), and hashes their paths + mtimes into a stamp so regeneration only happens when inputs changed ([`binding.cmake`](src:build/binding.cmake#L44)). Generation runs `binding_generator/scripts/starfish_code_generator.py` via `EXECUTE_PROCESS` ([`binding.cmake`](src:build/binding.cmake#L68)); only content-changed files are copied into `starfish_generated/binding/generated` to avoid needless recompiles ([`binding.cmake`](src:build/binding.cmake#L84)), stale outputs of deleted IDLs are removed ([`binding.cmake`](src:build/binding.cmake#L98)), and a `generate_binding` custom target depends on the generated `Interfaces.h` ([`generate_binding`](src:build/binding.cmake#L114)).

**Build targets (ninja).** The three documented targets ([`README.md`](src:README.md#L60)):

- `starfish.executable` — the shell executable ([`ADD_EXECUTABLE`](src:build/starfish_shell.cmake#L155)); its output file is named from `TARGETNAME` ([`starfish_shell.cmake`](src:build/starfish_shell.cmake#L179)).
- `starfish.shared_library` — `liblightweight-web-engine.so` ([`ADD_LIBRARY`](src:build/starfish.cmake#L143)).
- `starfish.static_library` — `liblightweight-web-engine.a` ([`ADD_LIBRARY`](src:build/starfish.cmake#L144)).

Output lands in `out/release` (or `out/debug`) with `bin/lightweight-web-engine` and a `lib/` directory of needed shared libraries ([`README.md`](src:README.md#L104)); run as `./out/release/lightweight-web-engine 'html/file/path'` ([`README.md`](src:README.md#L115)). The Windows build instead uses `cmake --build ... --target starfish.windows_shell`, which also builds `Starfish.dll` ([`README.md`](src:README.md#L237), [`README.md`](src:README.md#L252)).

**Cross-compilation (Linux aarch64 / armhf / x86).** Option A is a Docker image baking cross toolchains and sysroots under `/opt/sysroot/{aarch64,arm,x86}` (`Dockerfile.starfish`, `mk-sysroot.sh`, `build_starfish_docker.sh`) ([`README.md`](src:README.md#L128)). Option B exports `SYSROOT`, `T` (triple), `CC/CXX/AR/RANLIB/STRIP`, `CFLAGS/CXXFLAGS/LDFLAGS` and `PKG_CONFIG_LIBDIR`/`PKG_CONFIG_SYSROOT_DIR`, then passes `-DCMAKE_SYSTEM_NAME=Linux -DCMAKE_SYSTEM_PROCESSOR=aarch64 -DCMAKE_SYSROOT=... -DCMAKE_FIND_ROOT_PATH=...` ([`README.md`](src:README.md#L157)). The cross toolchain's glibc must be the same or newer than the target's ([`README.md`](src:README.md#L123)). Tizen builds go through GBS ([`README.md`](src:README.md#L194)); Android builds run `gradle build` in `build/android/apk` with `ANDROID_HOME` set and `android-ndk-r16b` ([`README.md`](src:README.md#L285)).

## Packaging and Deployment

**Tizen RPM.** [`lightweight-web-engine.spec`](src:packaging/lightweight-web-engine.spec#L19) declares, literally: `Name: lightweight-web-engine`, `Summary: Lightweight Web Engine for Tizen`, `Version: 1.5.2`, `Release: 1`, `Group: Development/Libraries`, and `License: LGPL-2.1+ and BSD-2-Clause and BSD-3-Clause and BSL-1.0 and MIT and ISC and Zlib and BOEHM-GC and ICU` ([`License`](src:packaging/lightweight-web-engine.spec#L24)). The `build_profile` macro selects `tv | headless | mobile | wearable | all`, defaulting to `all` ([`build_profile`](src:packaging/lightweight-web-engine.spec#L43)); product-type macros can remap it to `headless`/`prod_tv`/`wearable` ([`_vd_cfg_product_type`](src:packaging/lightweight-web-engine.spec#L68)). On Tizen the CMake build additionally produces TPK/UWE packaging targets (`starfish_shell_tpk.cmake`, `starfish_uwe_tpk.cmake`, `starfish_uwe_service.cmake`, with `UWE_PACKAGE_ID "org.tizen.lightweight-web-engine"`) ([`CMakeLists.txt`](src:CMakeLists.txt#L105)).

**Docker build images.** [`Dockerfile.starfish-build`](src:docker/Dockerfile.starfish-build#L16) is the CI build image: `FROM ubuntu:24.04`, installing the core toolchain (incl. `abigail-tools` for ABI-break detection) ([`Dockerfile.starfish-build`](src:docker/Dockerfile.starfish-build#L26)), the README's library dev packages ([`Dockerfile.starfish-build`](src:docker/Dockerfile.starfish-build#L58)), Python 3 + Jinja2 for the binding generator ([`Dockerfile.starfish-build`](src:docker/Dockerfile.starfish-build#L87)), Xvfb/imagemagick/fonts for tests ([`Dockerfile.starfish-build`](src:docker/Dockerfile.starfish-build#L100)), and baking in the WPT `Ahem.ttf` reference font ([`Dockerfile.starfish-build`](src:docker/Dockerfile.starfish-build#L116)). [`Dockerfile.android-build`](src:docker/Dockerfile.android-build#L23) is `FROM circleci/android:api-30-ndk`; it repoints EOL Debian Buster apt to `archive.debian.org` ([`Dockerfile.android-build`](src:docker/Dockerfile.android-build#L35)), installs the native toolchain plus `python3` with `Jinja2` and `ply` for the binding generator ([`Dockerfile.android-build`](src:docker/Dockerfile.android-build#L61)), bakes in the pinned SDK components `platforms;android-33`, `ndk;21.0.6113669`, `cmake;3.10.2.4988404` ([`sdkmanager`](src:docker/Dockerfile.android-build#L76)), and pre-warms Gradle 7.6.1 under a fixed `GRADLE_USER_HOME=/opt/gradle-home` ([`Dockerfile.android-build`](src:docker/Dockerfile.android-build#L107)). Both are published by `docker_build_push.yml`; the Windows MSVC-on-Wine cross-build image is explicitly *not* built in this repository ([`docker_build_push.yml`](src:.github/workflows/docker_build_push.yml#L17)).

**Windows vcpkg manifest.** [`vcpkg.json`](src:vcpkg.json#L2) defines manifest `starfish-windows` ("Windows x86/x64 native dependency graph for Starfish") with dependencies: `curl` (features `ssl`, `sspi`, `default-features: false`), `libwebsockets`, `cairo` (features `fontconfig`, `freetype`), `harfbuzz` (feature `freetype`), `fontconfig`, `freetype`, `giflib`, `glew`, `libpng`, `pthreads` ([`dependencies`](src:vcpkg.json#L5)). [`vcpkg-configuration.json`](src:vcpkg-configuration.json#L4) pins the builtin registry baseline `06d00ffa491e4668627728f14b891d22c6fea146` and registers `./vcpkg/ports-public` as an overlay so the repository's patched ports (cairo, libwebsockets) are used by every build without a command-line flag ([`overlay-ports`](src:vcpkg-configuration.json#L6), [`README.md`](src:README.md#L216)). The first CMake configure installs these dependencies; vcpkg's dynamic triplets' runtime DLLs and Fontconfig configuration are copied beside `Starfish.dll`, and a target Windows system must provide the Visual C++ runtime and the Windows system `icu.dll` API ([`README.md`](src:README.md#L267)). A binary cache can be enabled via `VCPKG_BINARY_SOURCES` for repeated builds ([`README.md`](src:README.md#L276)).
